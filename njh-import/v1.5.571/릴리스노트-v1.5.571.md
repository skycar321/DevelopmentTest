## 이 키트가 담는 것

- v1.5.570(전 키트)의 기능 전체에 더해, 아래 변경이 들어갔습니다. 구성은 이전 정식 키트와 동일합니다: 클라이언트(njh-cli), 게이트웨이(njh-gateway), 노트북 검증 킷(njh-win-laptop), Ollama Windows CPU 런타임, OCR 엔진, 빌드 매니페스트, SHA-256 매니페스트.
- 설치 절차와 현장값 관리 방식은 바뀌지 않았습니다. 현장값은 `~/.njh-cli/site.env` 한 파일에만 두고, 설치 명령은 용량 확인 → 전체 사전 점검 → 실제 설치 순서를 그대로 따릅니다.

## 수신자 관점의 주요 변화

- **마우스 드래그로 화면 내용을 복사할 수 있습니다**: Windows Terminal 에서 njh-cli 를 쓰는 동안 터미널의 드래그 선택·복사가 막히던 문제를 고쳤습니다. 파일을 끌어다 놓아 경로를 넣는 것도 함께 복구됩니다. 원인은 njh-cli 가 마우스 입력을 가져가면서 터미널에게서 선택 기능을 빼앗은 것이었고, 이제 평소 화면에서는 마우스를 가져가지 않습니다. 휠 스크롤이나 팝업 클릭이 필요하면 `NJH_MOUSE_TRACKING=1` 로 켤 수 있습니다(그 대신 드래그 복사를 포기하는 교환입니다).
- **전체화면 모드에서도 드래그 선택이 됩니다**: 전체화면은 화면을 직접 소유하므로 마우스를 가져갑니다. 그 대신 제공하던 "드래그하면 클립보드로 복사" 기능이 기본으로 꺼져 있어, 빼앗기만 하고 돌려주지 않는 상태였습니다. 이제 기본으로 켜지고, **드래그하는 동안 선택 범위가 화면에 반전되어 보입니다**.
- **`TERM=dumb` 터미널에서 ANSI 화면을 열지 않습니다**: 색과 커서 제어를 쓸 수 없다고 선언한 터미널에서도 전체화면과 확장 UI 프롬프트가 열려 있던 문제를 고쳤습니다.
- **터미널별 기능 판정을 한 곳에 모았습니다**: 어떤 터미널에서 어떤 기능이 켜지는지 `njh --debug-sticky` 의 `capabilities:` 줄에서 한 번에 볼 수 있습니다. 현장에서 "상태줄이 안 보인다", "복사가 안 된다" 를 진단할 때 이 한 줄이면 갈립니다.
- **상태 표시를 입력창 아래 두 줄로 옮기는 새 방식(선택)**: 화면 맨 위 고정 3줄과 맨 아래 고정 상태줄 대신, 입력창 바로 아래 두 줄만 쓰는 방식을 넣었습니다. 화면 줄을 덜 차지하고, 창 크기를 줄일 때 위쪽 내용이 덮이는 문제가 없으며, 같은 상태줄이 스크롤 기록에 쌓이지 않습니다. **기본은 꺼져 있습니다** — `settings.json` 에 `"terminal": { "liveStatusRegion": true }` 를 넣으면 켜지고, 그 줄을 지우면 이전 화면으로 돌아갑니다.
- **작업 중 출력이 겹쳐 글자가 붙던 문제를 구조적으로 없앴습니다**: 진행 표시와 로그가 서로 다른 시점에 화면을 건드리면서 같은 줄에 겹쳐 쓰이던 현상을, 지우기·쓰기·다시 그리기를 한 번에 내보내도록 바꿔 해소했습니다.
- **화면 회귀 검사망을 복구했습니다**: 8개 터미널 × 90개 시나리오 자동 검사가 60/720 만 실행되던 상태였습니다(한 시나리오가 실패하면 그 뒤가 통째로 건너뛰어졌습니다). 720/720 전부 실행되도록 고쳤고, 앞으로 화면 관련 변경은 이 검사를 통과해야 배포됩니다.

## 서버에서 돌리기 전에

- Node.js 요건은 `22.13.0+` 로 변함이 없습니다. 분리 미션·`/goal` 운용 절차는 `서버-운영-가이드.md` 가 정본이고, 미션이 커밋까지 하게 하려면 `미션-git-쓰기-정책.md` 의 두 스위치를 모두 켜야 합니다.
- 키는 환경 변수에만 넣고 설정 파일에는 환경 변수의 이름만 둡니다. 키 값, 호스트, 조직명은 문서·로그·설정 파일에 기록하지 않습니다.

## 설치 전에 확인할 것

- 이전 키트에서 안내한 사전 점검·보관·거부 규칙이 그대로 적용됩니다. 처음 설치하거나 절차가 기억나지 않으면 키트에 동봉된 `통합-설치가이드`와 `02-설치-및-업데이트` 문서를 먼저 읽으십시오.
- 기존 서비스 디렉터리는 삭제하거나 덮어쓰지 않고 시각이 붙은 형제 디렉터리로 보존되며, Ollama 모델 저장소는 그대로 유지됩니다.
