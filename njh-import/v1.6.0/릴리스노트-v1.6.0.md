## 이 키트가 담는 것

- v1.5.571(전 키트)의 기능 전체에 더해, 아래 변경이 들어갔습니다. 구성은 이전 정식 키트와 동일합니다: 클라이언트(njh-cli), 게이트웨이(njh-gateway), 노트북 검증 킷(njh-win-laptop), Ollama Windows CPU 런타임, OCR 엔진, 빌드 매니페스트, SHA-256 매니페스트.
- 설치 절차와 현장값 관리 방식은 바뀌지 않았습니다. 현장값은 `~/.njh-cli/site.env` 한 파일에만 두고, 설치 명령은 용량 확인 → 전체 사전 점검 → 실제 설치 순서를 그대로 따릅니다.

## 수신자 관점의 주요 변화

- **tmux 안에서 대기 줄이 쌓이지 않습니다**: 모델 응답을 기다리는 동안 15초마다 `응답 대기 30s — …` 줄이 새로 찍히고 앞에 상태 문자열이 붙어 화면이 흘러내리던 문제를 고쳤습니다. 이제 대기 상태는 **한 줄**에서만 갱신되고, 응답이 오면 `↩ 모델 첫 응답 Ns` 한 줄만 남습니다. 원인은 이 갱신이 화면 맨 아래 고정 상태줄 방식에서만 동작하고 tmux 같은 폴백 화면에서는 매번 새 줄을 만들던 것이었습니다.
- **진행 스피너가 돌아왔습니다**: 대기 줄 맨 앞에 회전 표시와 경과 초(`⠋ 12s 응답 대기 | …`)가 다시 나옵니다. 상태 문자열을 조립하면서 회전 표시를 버리던 것을 고쳤습니다.
- **tmux 를 정식 터미널로 인식합니다**: `TERM_PROGRAM=tmux`·`TERM=screen*/tmux*` 를 고정 상태줄이 가능한 터미널로 판정합니다. `--alternate-screen never` 로 띄워도 위 두 항목은 동일하게 적용됩니다.
- **긴 명령을 한 글자씩 입력할 때 첫 줄이 여러 번 남던 문제를 고쳤습니다**: 줄바꿈 경계를 두 번 넘는 긴 입력에서 입력창의 첫 줄이 잘린 채 반복해서 남던 현상입니다.
- **모델이 하나도 없는 Ollama 서버에 조용히 기다리지 않습니다**: 서버가 모델 0개를 보고하면 시작 시와 요청 시에 즉시 원인과 조치를 알립니다. 자동으로 띄우는 로컬 Ollama 서버에는 모델 저장소 위치(`OLLAMA_MODELS`)를 명시해 넘기며, 띄운 서버에 모델이 없는데 다른 로컬 서버에는 있으면 두 주소를 함께 알립니다.
- **`/goal` 이 아무것도 고치지 않고 "완료" 를 선언하지 못합니다**: 구현 성격의 목표(변환·이관·수정 등)는 실제 파일 변경 도구가 한 번 이상 성공해야 `GOAL_DONE` 을 받아들입니다(`--require-artifact` / `--no-require-artifact` 로 조정). 검증되지 않은 턴의 완료 선언도 거부합니다.
- **`/goal` 이 도구 반복 한도에 걸려도 멈추지 않고 이어갑니다**: 목표가 살아 있는 동안 턴당 도구 반복 한도를 최대(25)로 올리고, 한도 소진은 실패가 아니라 "이어가기" 로 처리합니다. 다음 반복에는 지금까지 고친 파일·돌린 명령·마지막 판정·최근 실패 증거를 담은 **진행 원장**이 전달되어 같은 파일을 다시 읽거나 같은 자리에서 맴도는 일을 막습니다.
- **약한 모델의 도구 호출이 인자 하나 때문에 통째로 막히지 않습니다**: 선언되지 않은 인자만 문제일 때는 그 인자를 떨구고 실행합니다(로컬 약모델 복구 옵션이 켜진 경우). 이전에는 같은 호출이 반복 거부되어 진행이 0 이 되는 사례가 있었습니다.
- **Vue 3 마이그레이션 킷 — 소견별 완주 드라이버**: 번들 스킬 `vue3-migration` 의 드라이버(`phase1-driver.mjs`, 초안 킷 18단계가 호출)가 검출기 소견을 하나씩 bounded `/goal` 로 처리하고, 소견마다 재검출 결과를 판정(`KIT_SUFFICIENT`·`RESIDUE_REMAINS`·`REVIEW_ESCALATED`(주석만 남긴 §6 정지 사례 = 운영자 결정 항목)·`BLOCKED_STATED`·`TIMEOUT`·`NO_GUIDE`)해 증거 파일로 남깁니다. 검출기 침묵은 런타임 동등성의 증거가 아니라는 점을 판정 노트에 명시합니다.
- **킷 가이드 — 본 변환 문서와 가이드 6편 추가**: 소견 코드별 가이드가 다루지 않던 본 변환(`xlsx → exceljs`)을 `00-BASE-CONVERSION.md` 로 세우고 모든 가이드가 이를 먼저 가리킵니다. 조치 표에 있으나 가이드가 없던 코드(`ASYNC_TRANSACTION_BLOCKED`·`DEGRADED_PARSER`·`EXPORTED_ASYNC_CONTRACT`·`MODULE_ALIAS_CONFIG_REVIEW`·`MODULE_IMPORT_RESOLUTION_REVIEW`)와 조치 표 밖에서 실제로 나오는 코드(`TEMPLATE_HANDLER_MAP`·`ASYNC_CALLBACK_BOUNDARY`·`ASYNC_FUNCTION_ESCAPE`)의 가이드를 채웠습니다(런타임 증인이 없는 편은 UNVERIFIED 로 표기).
- **킷 동등성 판정기가 출하 레이아웃에서 다시 돕니다**: 케이스별 `verify.cjs` 가 랩 전용 상대경로를 보고 있어 31편 중 9편만 실행되던 것을 28편으로 복구했습니다. 남은 2편(`OUTPUT_RULE_GATE` 환경 요구, `DYNAMIC_INSTANCE_REFERENCE` 코드 불일치)은 문서에 사유를 적어 두었습니다.
- **화면 회귀 검사망에 tmux 프로파일이 들어갔습니다**: 이전까지 9개 중 0개였던 다중화기 화면이 검사 대상이 됐고(9 터미널 × 90 시나리오), 실제 tmux 안에서 가짜 지연 서버로 대기 화면을 캡처해 판정하는 검사(`npm run e2e:tmux:inline-wait`)를 추가했습니다.

## 서버에서 돌리기 전에

- Node.js 요건은 `22.13.0+` 로 변함이 없습니다. 분리 미션·`/goal` 운용 절차는 `서버-운영-가이드.md` 가 정본이고, 미션이 커밋까지 하게 하려면 `미션-git-쓰기-정책.md` 의 두 스위치를 모두 켜야 합니다.
- 키는 환경 변수에만 넣고 설정 파일에는 환경 변수의 이름만 둡니다. 키 값, 호스트, 조직명은 문서·로그·설정 파일에 기록하지 않습니다.

## 설치 전에 확인할 것

- 이전 키트에서 안내한 사전 점검·보관·거부 규칙이 그대로 적용됩니다. 처음 설치하거나 절차가 기억나지 않으면 키트에 동봉된 `통합-설치가이드`와 `02-설치-및-업데이트` 문서를 먼저 읽으십시오.
- 기존 서비스 디렉터리는 삭제하거나 덮어쓰지 않고 시각이 붙은 형제 디렉터리로 보존되며, Ollama 모델 저장소는 그대로 유지됩니다.
