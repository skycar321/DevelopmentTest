## 이 키트가 담는 것

- v1.5.565(전 키트)의 기능 전체에 더해, 아래 변경이 들어갔습니다. 구성은 이전 정식 키트와 동일합니다: 클라이언트(njh-cli), 게이트웨이(njh-gateway), 노트북 검증 킷(njh-win-laptop), Ollama Windows CPU 런타임, OCR 엔진, 빌드 매니페스트, SHA-256 매니페스트.
- 설치 절차와 현장값 관리 방식은 바뀌지 않았습니다. 현장값은 `~/.njh-cli/site.env` 한 파일에만 두고, 설치 명령은 용량 확인 → 전체 사전 점검 → 실제 설치 순서를 그대로 따릅니다.

## 수신자 관점의 주요 변화

- **고정 상태줄과 입력창 테두리가 기본값에서 나옵니다**: Windows Terminal(Git Bash 프로필 포함)에서 설정 파일을 하나도 건드리지 않아도 상단 고정 헤더와 하단 상태줄이 렌더됩니다. 지금까지는 `terminal.uiMode` 를 손으로 `full` 로 바꾸고 환경 변수까지 줘야 나타났습니다. 원인은 세 겹이었고, 그중 DECSTBM 능력 프로브는 **수행하는 코드가 아예 없어서** 갓 설치한 상태가 영구히 "미확인" 으로 남아 있었습니다. 이제 터미널 허용목록이 능력을 판정하고, 프로브 값은 거부용 예외 선언으로만 씁니다.
- **끄는 방법은 그대로 남아 있습니다**: 상태줄이 맞지 않는 터미널에서는 `terminal.uiMode` 를 `conservative` 로 두거나 `NJH_NO_SCROLL_REGION=1` / `NJH_DISABLE_WT_SCROLL_REGION=1` 을 주면 이전과 같은 append-only 렌더로 돌아갑니다. 창 크기 변경 시 전사 보존 경로는 바뀌지 않았습니다.
- **ESC 안내가 같은 두 줄을 쌓지 않습니다**: 하단 고정 상태줄이 없는 터미널에서 ESC 를 누를 때마다 같은 안내가 새로 append 돼 화면을 채우던 문제를 고쳤습니다. 같은 문구가 이미 떠 있으면 입력줄만 되살립니다.
- **본문 한 줄이 출력된 뒤에도 진행 표시가 남아 있습니다**: 응답 본문을 찍는 순간 그 위의 스피너 행이 지워진 채로 남아 작업이 멈춘 것처럼 보이던 문제를 고쳤습니다.

## 서버에서 돌리기 전에

- Node.js 요건은 `22.13.0+` 로 변함이 없습니다. 분리 미션·`/goal` 운용 절차는 `서버-운영-가이드.md` 가 정본이고, 미션이 커밋까지 하게 하려면 `미션-git-쓰기-정책.md` 의 두 스위치를 모두 켜야 합니다.
- 키는 환경 변수에만 넣고 설정 파일에는 환경 변수의 이름만 둡니다. 키 값, 호스트, 조직명은 문서·로그·설정 파일에 기록하지 않습니다.

## 설치 전에 확인할 것

- 이전 키트에서 안내한 사전 점검·보관·거부 규칙이 그대로 적용됩니다. 처음 설치하거나 절차가 기억나지 않으면 키트에 동봉된 `통합-설치가이드`와 `02-설치-및-업데이트` 문서를 먼저 읽으십시오.
- 기존 서비스 디렉터리는 삭제하거나 덮어쓰지 않고 시각이 붙은 형제 디렉터리로 보존되며, Ollama 모델 저장소는 그대로 유지됩니다.
