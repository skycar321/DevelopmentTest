## GPU 가 CPU 로 떨어지던 문제 — 원인과 조치

원인은 **부하가 아니라 버전 불일치**였습니다.

`start-local-llm.sh` 가 모델을 `num_batch=256` 으로 GPU 에 올리는데, njh 가
**v1.5.226** 이면 그 옵션을 아예 모릅니다(이해하기 시작한 건 v1.5.228). 그래서 njh 가
그 옵션 없이 요청 → ollama 는 적재 옵션이 하나라도 다르면 모델을 **통째로 다시 적재** →
그 재적재가 RAM 압박 상태에서 CPU 로 착지. "호출테스트 치자마자 CPU 100%" 가 이것입니다.

**따라서 CLI 킷 교체가 핵심입니다.** 그동안 안내에 "CLI 킷은 v1.5.226 그대로"라고
적혀 있었는데, 그 사이 런타임이 바뀌었습니다. 잘못된 안내였습니다.

## 설치

```bash
# 1) CLI 킷을 기존 njh 설치 위치에 풀고 설치
#    ⚠️ 예전 v1.5.226 폴더의 njh 는 쓰지 마세요. PATH 도 새 위치로.
njh --version        # v1.5.238 확인

# 2) 노트북 로컬 LLM 도구
cd /c/njh-local-llm
./verify-local-llm.sh     # ← 먼저 이걸 돌리세요 (아래 [7] 참고)
./start-local-llm.sh      # GPU 상주
njh                       # 호출테스트
ollama.exe ps             # PROCESSOR 가 GPU 로 유지되면 끝
```

## 이번에 추가된 것

**① 튜닝이 최선 조합에서 끝납니다** — 첫 조합(최대 컨텍스트+최대 배치)이 통과하면
그보다 나은 조합은 존재하지 않으므로 나머지를 생략합니다. 전 조합을 다 재면 실측
기준 3시간이었는데, 이제 보통 **15~25분**에 끝납니다.

**② `verify-local-llm.sh` 에 [7] 적재 옵션 검증** — njh 를 켜기 전에 원인을 잡습니다:
- 판정 파일 / `settings.json` / 이 창의 환경변수가 **같은 옵션**을 가리키는지 대조
- PATH 의 njh 가 **v1.5.228 이상**인지 (미만이면 무조건 재적재를 유발)

**③ `start-local-llm.sh` 환경변수 충돌 경고** — 예전 판정 때 박힌 `NJH_OLLAMA_*` 가
이미 열린 창에 남아 있으면 경고하고 정리 명령을 알려줍니다.

**④ 이미 GPU 상주 중이면 건드리지 않습니다** — 모델 자신이 6GB 를 쓰므로 여유 RAM
2GB 미만이 정상인데, 예전에는 그걸 보고 실행을 거부했습니다.

## 게이트웨이 (AP03, 선택)

모니터의 "경과"가 0 → 4초 → 0 으로 되돌아가던 문제를 고쳤습니다(재라우팅마다 시작
시각이 초기화되던 것). `stop.sh` → 압축 해제 → `start.sh`.
