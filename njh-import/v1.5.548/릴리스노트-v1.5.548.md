# njh-cli 교체 키트 릴리스 노트 — v1.5.548 (2026-09-01)

이 문서는 `v1.5.548` 교체 키트와 함께 전달됩니다. v1.5.547 직후의 문서 보강판이며 실행 파일 변경은 없습니다. 키트와 체크섬(`SHA256SUMS.txt`)이 정식으로 전달되고 검증되기 전에는 기존 설치에 이 절차를 적용하지 마십시오.

## 이 키트가 담는 것

- 마지막 전달본(v1.5.479 채널 게시) 이후 허브에서 검증·통합된 변경 전체를 하나의 교체 키트로 전달합니다(소스 기준 v1.5.479 → v1.5.548 누적 통합).
- 구성은 이전 정식 키트와 동일합니다: 클라이언트(njh-cli), 게이트웨이(njh-gateway), 노트북 검증 킷(njh-win-laptop), Ollama Windows CPU 런타임, OCR 엔진, 빌드 매니페스트, SHA-256 매니페스트.
- 설치 절차와 현장값 관리 방식은 바뀌지 않았습니다. 현장값은 `~/.njh-cli/site.env` 한 파일에만 두고, 설치 명령은 용량 확인 → 전체 사전 점검 → 실제 설치 순서를 그대로 따릅니다. 앞 단계가 실패하면 다음 단계로 넘어가지 않습니다.

## 수신자 관점의 주요 변화

- **v1.5.548 보강**: `02-설치-및-업데이트.md`와 `06-post-import-first-30-minutes.md`에 설치 시 `CAPACITY REFUSE`가 표시될 때의 대응 절차(재시작 금지, 출력 수치로 모델·컨텍스트·JVM 배치 조정 후 재실행)를 추가했습니다.

- **설치기·릴리스 게이트 안전장치 강화**: 사전 점검, 용량 부족 시 `CAPACITY REFUSE`, 기존 설치 보관 우선 원칙이 유지·강화되었고, 배포되는 모든 셸 스크립트가 수신 환경의 셸에서 실제로 파싱되는지 릴리스 전에 검증됩니다.
- **Windows 호환 수정 누적**: 배포되는 PowerShell 스크립트에 UTF-8 BOM이 보장되는 등 Windows 터미널·셸 계열의 실사용 결함 수정이 포함되었습니다.
- **터미널 UI 사용성 수정 누적**: 좁은 폭(24~58컬럼) 시작 화면 보존, 혼합 폭 유니코드 입력 처리, 중단·복구 표시의 정확성 등 실사용 결함 수정이 포함되었습니다.
- **수신자 문서 계약 검증 확대**: 설치 가이드가 지시하는 진단기·경로가 실제 배포물과 일치하는지 실행 가능한 테스트로 릴리스마다 검증됩니다.
- **로컬 모델 운용 문서 최신화**: 서버 기본 모델(gemma4:12b) 운용과 임베딩 경로 문서가 현행화되었습니다.

## 설치 전에 확인할 것

- 이전 키트에서 안내한 사전 점검·보관·거부 규칙이 그대로 적용됩니다. 처음 설치하거나 절차가 기억나지 않으면 키트에 동봉된 `통합-설치가이드`와 `02-설치-및-업데이트` 문서를 먼저 읽으십시오.
- 기존 서비스 디렉터리는 삭제하거나 덮어쓰지 않고 시각이 붙은 형제 디렉터리로 보존되며, Ollama 모델 저장소는 그대로 유지됩니다.

## 설치 후 확인

설치 명령이 성공하면 Ollama 상태를 확인하고, Gateway 역할이 포함된 서버에서는 보관 디렉터리 존재 확인 후 Gateway smoke를 실행하십시오. 설치 중 호스트가 응답하지 않거나 `CAPACITY REFUSE`가 표시되면 서버를 직접 재시작하지 말고 인프라 담당자에게 요청하십시오.
