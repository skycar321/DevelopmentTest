## 이 버전에서 고친 것

### 1. 자동 워크플로우 구조적 데드락 (시연 차단 결함)
"현재 프로젝트를 분석하고 요약 md 만들어줘" 같은 기본 과제가 완주하지 못하던 원인입니다.
자동 워크플로우 청크가 구조화 출력(schema)을 강제하는데, 그 제약 아래에서 도구 호출을 내지
못하는 백엔드는 JSON 판정문만 반환합니다. 그런데 그 판정문의 검증 조건이 "도구로 읽은 실파일
근거 인용"이라 **구조적으로 100% 실패**했습니다(2026-08-05 현장 재현: 2분 1초, 산출물 0).

→ `workflow.auto` 기본값을 **OFF**로 바꿨습니다. 일반 에이전트 루프가 도구를 호출해 완주합니다.
로컬 재현에서 도구 호출 **0회 → 13회**로 확인했습니다. 켜려면 `settings.json` 의
`workflow.auto: true`.

### 2. 게이트웨이 워밍 HTTP 400 (AP03 설치 실패의 뿌리)
배포 시드가 `keepAlive: "-1"` 이었는데, ollama 는 **문자열** `"-1"` 을 duration 으로 파싱하지 못해
요청을 거부합니다(`time: missing unit in duration "-1"`). 연쇄: 워밍 400 → 백엔드 3대 전부
`model_not_warmed` → 라우팅 불가 → 6-caller E2E 503 → **설치 롤백**.

→ 시드 4곳을 `"24h"` 로 교체하고, 검증기가 `-1` 과 단위 없는 정수(`"600"` — 실측상 같은 400)를
원인·조치와 함께 거부합니다. 기존 설치본에 남은 legacy 값은 기동 실패 대신 자동 이관됩니다.

### 3. 롤백 경로의 unbound 변수
`setup-gateway.sh` 의 실패 처리기가 존재하지 않는 변수를 참조해 `set -u` 아래에서 죽었고,
그 결과 **설치본이 통째로 사라졌습니다**(`NO ACTIVE GATEWAY CONFIGURATION REMAINS`).

### 4. 모델 상주 단계 누락
`install-all.sh model` 이 모델 "등록"까지만 하고 끝나, 노드가 러너 없는 상태로 남아 매 요청마다
4.7GB 를 다시 읽었습니다(짧은 질문에 46초). 이제 상주 설정까지 자동으로 수행합니다.

### 5. 로컬 프로파일이 GPU 를 강제로 끄던 문제
배포 기본값이 현장 CPU 서버 형상을 그대로 베껴 `numGpu: 0` 을 싣고 있었습니다. 개인 PC·노트북·맥
에서 njh-cli 가 스스로 GPU 를 껐습니다(실측: 미지정 → 41.8 tok/s, `0` → 4.3 tok/s = **9.7배**).

## 설치 순서

```
# 모델 노드 (AP01, AP02)
./install-all.sh model

# 모델 + 게이트웨이 겸용 노드 (AP03)
./install-all.sh both
```

인자 없이 실행하면 저장된 역할로 진행합니다. 사이트 설정은 최초 1회만 묻고 `~/.bashrc` 의
`# >>> njh-site >>>` 블록에 저장됩니다. root 권한을 쓰지 않습니다.

## 알려진 제약

- KV 캐시 기본값은 `f16` 입니다. `num_ctx 32768 × 56KiB/token = 1792MiB` 가 노드 예산을 넘으면
  설치가 중단되면서 통과하는 명령을 계산해 알려줍니다
  (`--kv-cache-type q8_0 --flash-attention 1`, 요구량 952MiB).
  q8_0 을 기본값으로 삼지 않는 이유는 counterbalanced 측정에서 prompt_eval 이 **+33% 느렸기**
  때문입니다(물리 1코어 현장은 prefill 이 병목).
