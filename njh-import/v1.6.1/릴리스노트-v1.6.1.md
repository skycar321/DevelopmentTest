## 이 키트가 담는 것

- v1.6.0(전 키트)의 기능 전체에 더해, 아래 변경이 들어갔습니다. 구성은 이전 정식 키트와 동일합니다: 클라이언트(njh-cli), 게이트웨이(njh-gateway), 노트북 검증 킷(njh-win-laptop), Ollama Windows CPU 런타임, OCR 엔진, 빌드 매니페스트, SHA-256 매니페스트.
- 설치 절차와 현장값 관리 방식은 바뀌지 않았습니다. 현장값은 `~/.njh-cli/site.env` 한 파일에만 두고, 설치 명령은 용량 확인 → 전체 사전 점검 → 실제 설치 순서를 그대로 따릅니다.

## 수신자 관점의 주요 변화

- **설치 3단계(번들 스킬 복사)가 다시 수초에 끝납니다**: v1.6.0 설치에서 `bundled-skills` 벌크 설치가 Windows 에서 `EPERM` 으로 미끄러지면 파일 단위 복사로 떨어져 30분 넘게 "N개 처리" 만 찍히던 문제를 고쳤습니다. 원인은 두 가지였습니다 — (1) 갓 복사한 트리를 백신이 스캔하는 동안 폴더 이름 바꾸기가 `EPERM` 으로 거부되는데 설치기가 `EBUSY` 만 재시도했고, (2) 아카이브 8,258 파일 중 7,904 이 `vue3-migration` 스킬 하나에 쌓인 실험실 연구 자료(참조 팩·코퍼스·픽스처)여서 복사할 파일이 지나치게 많았습니다. 이제 이름 바꾸기가 `EPERM`/`EBUSY` 로 계속 거부되면 설치기가 **Node 안에서 통째로 복사**해 끝내고, 아카이브는 **2,137 파일**만 싣습니다.
- **`vue3-migration` 스킬은 런타임 파일만 실립니다**: `SKILL.md`·스크립트·소견 코드별 가이드(`references/detector-codes/`)·검출 절차(`references/detector-procedures/`)·작업 지시서(`references/work-orders/`)·루트 참조 문서·검출기 도구(`assets/detector-kit/{tools,verify,policies,rules}` + 동결 규칙 파일)·동작 계약 하네스(`assets/behavior-contract/`)는 그대로입니다. 빠진 것은 실험실 연구 팩(`references/pack-integration`·`false-positive-rate`·`ooxml-equivalence`·`order-dependent-state` 등), 검출기 코퍼스·기준선·벤치마크, 픽스처·테스트입니다 — 스킬 실행·가이드 링크·동결 규칙 검증 어느 것도 이들을 읽지 않습니다(전수 확인).
- **v1.6.0 설치를 중단했던 경우**: 클라이언트 번들·설정 업그레이드는 이미 끝나 있으므로 이 키트로 다시 설치하면 3단계만 새로 수행되고, 이전 스킬 트리는 `~/.njh-cli/skills.prev` 에 보존됩니다. Vue 3 초안 킷(32차)의 18단계는 킷 자신의 스킬 사본을 쓰므로 `~/.njh-cli/skills` 상태와 무관하게 동작합니다.

## 서버에서 돌리기 전에

- Node.js 요건은 `22.13.0+` 로 변함이 없습니다. 분리 미션·`/goal` 운용 절차는 `서버-운영-가이드.md` 가 정본이고, 미션이 커밋까지 하게 하려면 `미션-git-쓰기-정책.md` 의 두 스위치를 모두 켜야 합니다.
- 키는 환경 변수에만 넣고 설정 파일에는 환경 변수의 이름만 둡니다. 키 값, 호스트, 조직명은 문서·로그·설정 파일에 기록하지 않습니다.

## 설치 전에 확인할 것

- 이전 키트에서 안내한 사전 점검·보관·거부 규칙이 그대로 적용됩니다. 처음 설치하거나 절차가 기억나지 않으면 키트에 동봉된 `통합-설치가이드`와 `02-설치-및-업데이트` 문서를 먼저 읽으십시오.
- 기존 서비스 디렉터리는 삭제하거나 덮어쓰지 않고 시각이 붙은 형제 디렉터리로 보존되며, Ollama 모델 저장소는 그대로 유지됩니다.
