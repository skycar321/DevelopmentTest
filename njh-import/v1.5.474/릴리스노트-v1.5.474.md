# njh-cli 교체 키트 릴리스 노트 — v1.5.474 (2026-08-26)

이번 교체 키트는 v1.5.473의 OCR 현장 경로·모델 승인·비대화형 설치 보강에 더해, **기존 설치 위 업그레이드 절차와 그 검증 경로**를 공식화했습니다.

## 이전 키트를 받으셨다면

이전 전달분은 새 키트와 섞어 사용하지 마십시오. 수신한 아카이브 파일명과 `SHA256SUMS.txt`를 먼저 대조한 뒤, 이번 `v1.5.474` 전달분의 안내와 아카이브만 사용하십시오. 체크섬 또는 파일 구성이 맞지 않으면 설치하지 말고 새 전달분을 요청하십시오.

## OCR: AP별 엔진부터 PC 명령까지 하나의 경로

- 각 AP에서 `quick-install.sh --role ocr`로 오프라인 OCR 엔진과 OCR 게이트웨이 경로를 설치할 수 있습니다. 엔진은 각 AP의 로컬 루프백 작업자로 동작하고, 게이트웨이가 인증된 단일 접점으로 연결합니다.
- 게이트웨이 설치에는 브라우저 OCR 콘솔(`http://<접속주소>:<포트>/ocr`)과 인증된 스모크 검사가 포함됩니다. 스모크는 세 로컬 작업자, 토큰 인증 HTTP 응답, 동봉된 합성 신청서의 OCR 줄과 최소 한 개의 신청서 필드를 함께 확인합니다.
- PC의 `njh ocr <image>`와 `njh ocr doctor`는 OCR 게이트웨이 주소와 지정된 토큰 환경변수를 사용합니다. 실제 토큰은 명령줄·문서·로그에 기록하지 말고 승인된 환경변수로만 제공하십시오.
- OCR 엔진 아카이브는 서버 키트와 같은 상위 폴더의 `njh-ocr-engine` 디렉터리에 해제해야 합니다. 개별 엔진 파일을 키트 안으로 복사하지 말고, 누락 안내가 나오면 그 위치를 확인한 뒤 같은 bootstrap 명령을 다시 실행하십시오.

## 기존 서버 위 업그레이드가 공식 경로가 되었습니다 (v1.5.474 신규)

- `bootstrap-import.sh`가 기존 설치를 감지하면 업그레이드 경로를 안내합니다: 기존 서비스 정지 → `site.env` 보존(권한 600 사본) → 새 키트를 **형제 디렉터리**로 해제(기존 키트 위 덮어쓰기 금지) → 승인 현장값만 이관 → 완료 URL 확인 전까지 기존 키트 유지 → 실패 시 보존한 site 파일 복원과 기존 서비스 재기동으로 롤백.
- `docs/설치-원페이지.md`에 같은 내용의 **Upgrade 절**이 추가되어 카드 순서만 따라가면 됩니다.
- 업그레이드 후 실행되는 배포 E2E 검사가 보존된 기존 토큰 설정을 실행 게이트웨이와 같은 우선순위로 해석합니다. 이전에는 이 불일치로 검사 단계가 인증 오류(HTTP 401)로 중단될 수 있었습니다. 인증 검사 자체는 그대로 유지됩니다.

## 모델 승인 실패를 줄였습니다

- 설치 중 제한된 정확 응답을 확인하는 모델 승인 요청은 추론 출력을 끄고 검사합니다. 이는 승인용 짧은 응답이 별도 추론 채널로 이동해 빈 응답처럼 보이던 실패를 막기 위한 것으로, 일반 모델 사용의 추론 설정을 바꾸지 않습니다.
- 모델 이름의 태그를 생략한 이름과 `:latest` 태그는 같은 모델로 비교합니다. 다만 이름만으로 승인하지 않으며, 기존처럼 설치된 모델의 digest와 크기도 함께 대조합니다.

## 한 페이지 설치 카드: 현장 입력만 손으로 바꾸십시오

- `docs/설치-원페이지.md`의 직접 수정 대상은 `REPLACE_SITE_` 접두사가 있는 값뿐입니다. 반입 위치·설치 기반 경로·AP 주소·승인 CIDR·토큰 등 현장 승인값만 채우십시오.
- `--role all` 비대화형 설치에 필요한 9개 역할 공통 값(매칭 엔진·포트·모델 경로와 세 OCR 백엔드·OCR 게이트웨이 포트)은 카드에 기본값으로 채워져 있습니다. 기본값이 맞는 현장에서는 이 값을 다시 입력하지 않아도 됩니다.
- 카드의 순서대로 dry-run, 실제 설치, OCR 엔진 상태와 게이트웨이 스모크를 실행하십시오. 스모크 통과는 정해진 인프라 조건의 확인이지 실제 업무 문서 전체의 인식 정확도를 보장하는 결과는 아닙니다.

## 여섯 역할 안내가 같은 목록을 사용합니다

- 설치 역할의 기준 목록은 `model`/`gateway`/`embed`/`ocr`/`match`/`all`입니다. C5와 Gateway 키트에 함께 실리는 안내 문서가 이 목록과 일치하도록 동기화했습니다.
- 새 검사는 실제 설치기가 허용하는 역할 목록을 기준으로 모든 동봉 가이드의 역할 표기를 확인합니다. 이후 가이드 한 곳만 이전 목록으로 남아도 배포 전에 발견됩니다.

## 배포 채널을 만들 때의 검증도 강화했습니다

- 미리보기 리허설은 검토된 기준 소스에서 이어진 상태와 패키징 스크립트 허용 변경만 통과합니다. 다른 소스 변경이 섞인 리허설은 릴리스 후보로 사용하지 않습니다.
- OCR 엔진 `.7z`는 픽업을 만들기 전에 현재 릴리스 암호로 실제 무결성 검사를 합니다. 암호와 호환되지 않거나 손상된 아카이브는 채널에 올라가기 전에 거부됩니다.
- 릴리스 담당자는 한 번의 채널 업로드 명령으로 업로드 대상의 체크섬 매니페스트 생성·검사·게시 후 대조를 수행합니다. 수신자는 계속해서 별도 승인 채널로 받은 `SHA256SUMS.txt`의 신뢰 앵커와 수신 파일을 확인해야 합니다.

## 알려진 제한

- OCR 스모크와 모델 승인은 정해진 로컬·인증·응답 조건을 확인합니다. 실제 AP 네트워크, 현장 권한, 모든 업무 문서의 인식 결과 또는 일반 작업 품질을 대신 보증하지 않습니다.
- 토큰, 암호, 내부 주소, 인증서 값은 수신자 문서에 포함되지 않습니다. 값이 없거나 채널 검증이 실패하면 임의의 이전 값을 재사용하지 말고 담당자에게 승인값 또는 새 전달분을 요청하십시오.
