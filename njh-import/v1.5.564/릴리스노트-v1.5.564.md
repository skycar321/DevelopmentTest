## 이 키트가 담는 것

- v1.5.563(전 키트)의 기능 전체에 더해, 아래 변경이 들어갔습니다. 구성은 이전 정식 키트와 동일합니다: 클라이언트(njh-cli), 게이트웨이(njh-gateway), 노트북 검증 킷(njh-win-laptop), Ollama Windows CPU 런타임, OCR 엔진, 빌드 매니페스트, SHA-256 매니페스트.
- 설치 절차와 현장값 관리 방식은 바뀌지 않았습니다. 현장값은 `~/.njh-cli/site.env` 한 파일에만 두고, 설치 명령은 용량 확인 → 전체 사전 점검 → 실제 설치 순서를 그대로 따릅니다.

## 수신자 관점의 주요 변화

- **첨부 이미지가 도구 호출 뒤에도 유지됩니다(OpenAI 전송)**: 이미지를 붙여 질문한 뒤 모델이 도구를 한 번 쓰면 다음 요청에서 이미지가 빠지던 결함을 고쳤습니다. `api.codiNativeTools.imageHistoryTurns`(기본 2턴) 동안 첨부 이미지가 요청에 남습니다. 프록시 실측으로 전·후 요청 구성을 확인했습니다.
- **`view_image`·`read_file` 로 읽은 이미지를 모델이 실제로 봅니다**: 도구가 연 이미지가 다음 요청의 이미지 파트로 전달됩니다(OpenAI 전송 한정).
- **공백이 있는 경로도 `@경로` 첨부가 됩니다**: 따옴표 없이 적어도 실제 존재하는 가장 긴 경로로 인식합니다.
- **DevAI 연결은 연결 모델만 호출합니다**: `transport: "openai"` 연결은 메인·미니(서브에이전트)·병렬 요청 전부를 연결의 `model` 로 고정합니다. 다른 모델명이 섞이면 요청 직전에 연결 모델로 바꾸고 한 줄 알림(`연결 모델 고정`)을 냅니다. 연결별 `codiAgents.mini.model` 은 생략 시 연결 모델이 기본이며 시드 `openai-import` 프로파일에 명시했습니다(`allowedModels`·`strictModel` 로 조정). 미니 요청이 실패하면 메인 모델이 이어받아 `(no response)` 로 끝나지 않습니다.
- **연결 정체 라벨**: 같은 도메인을 쓰는 DevAI/Codi 연결이 "코디 직결(host)" 로만 보이던 것을 연결 라벨로 표기합니다.
- **`apiKeyEnv` 판별 정정**: 대문자·밑줄·하이픈만으로 된 이름은 비밀값이 아니라 잘못 적은 환경변수명으로 취급합니다(게이트웨이 전환 차단 안내 복원).
- **설정 진단 별칭 보강**: `tools.git` 별칭이 설정 진단 스크립트에 빠져 있던 것을 추가했습니다.
- **문서**: `OpenAI-서버-전송.md` 에 모델 고정·미니 위임·이미지 이력 절을 추가했고, `fileUploadApiKey` 는 Dify 전용이므로 OpenAI 전송 연결에서는 제거하도록 안내합니다.

## 서버에서 돌리기 전에

- Node.js 요건은 `22.13.0+` 로 변함이 없습니다. 분리 미션·`/goal` 운용 절차는 `서버-운영-가이드.md` 가 정본이고, 미션이 커밋까지 하게 하려면 `미션-git-쓰기-정책.md` 의 두 스위치를 모두 켜야 합니다.
- 키는 환경 변수에만 넣고 설정 파일에는 환경 변수의 이름만 둡니다. 키 값, 호스트, 조직명은 문서·로그·설정 파일에 기록하지 않습니다.

## 설치 전에 확인할 것

- 이전 키트에서 안내한 사전 점검·보관·거부 규칙이 그대로 적용됩니다. 처음 설치하거나 절차가 기억나지 않으면 키트에 동봉된 `통합-설치가이드`와 `02-설치-및-업데이트` 문서를 먼저 읽으십시오.
- 기존 서비스 디렉터리는 삭제하거나 덮어쓰지 않고 시각이 붙은 형제 디렉터리로 보존되며, Ollama 모델 저장소는 그대로 유지됩니다.
