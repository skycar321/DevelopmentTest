# Vue 3 초안 킷 — 9차

암호 7z(AES-256, 헤더 암호화). 암호는 njh-cli 킷과 같고 별도 채널로 전달된다.

## 받는 법

```bash
sha256sum -c sha256.txt          # 또는 shasum -a 256 -c sha256.txt
7z x -p'<암호>' vue3-draft-kit-20260910-9.7z
```

풀면 나오는 `vue3-carry-20260909-v2/` 안의 **`docs/뷰3-초안-사내-런북.md`**(같은 내용의 `.html`)가 절차 정본이다.
폐쇄망에서 브라우저로 볼 수 있게 HTML 은 외부 참조가 없는 단일 파일이다. 단계마다 `run/NN-*.sh` 한 줄이다.

## 새 터미널을 열 때마다 (첫 줄)

```bash
source "<킷 경로>/env.sh"
```

이 한 줄로 `$KIT` · `$V3` · `$WEB` · `$BASE_TAG` 가 살아난다. 런북의 명령은 이 값들을 쓴다.

## 이미 한 번 돌린 경우

```bash
# 킷을 새 폴더에 풀었다면 먼저 한 번 (같은 자리에 덮어썼으면 건너뛴다)
bash "<새 킷>/run/00a-adopt-kit.sh" <옛 킷 경로>

source "<킷 경로>/env.sh"
bash "$KIT/run/00b-resume.sh"        # 어느 단계부터 하면 되는지 한 줄로 찍는다(읽기 전용)
```

`00a` 는 옛 `env.sh` 를 그대로 가져오고 **`KIT` 경로만** 고친다. 진행 상태(`draft-hashes.txt` · 보고서 · 로그 ·
로그인 세션)도 함께 옮긴다. `00b` 는 출발 태그 · 워크트리 · 설치 · 초안이 어느 킷으로 만들어졌는지 · 게시 커밋 ·
연결 · 보고서 · 화면 렌더 실측을 차례로 보고 시작 지점을 찍는다.

**★ 킷만 바뀐 상황에서 `00-env.sh` 를 다시 돌리지 않는다.** 그 스크립트는 `BASE_TAG` 를 **오늘 날짜**로 만든다.
새 태그가 생기면 2단계가 최신 as-is 에서 새 기준선을 잡고, 나중에 "손댄 화면" 을 가려낼 수 없게 된다.
9차부터는 이미 `vue3-base-*` 태그가 있으면 `00-env.sh` 가 **거부하고** `00a` 를 안내한다.

## 8차에서 달라진 것

- `run/00a-adopt-kit.sh` 신설 — 킷을 새 폴더에 풀었을 때 옛 설정·진행 상태를 인수한다.
- `00-env.sh` 가 기준 태그가 이미 있으면 거부한다(두 번째 기준선 방지). `env.sh` 에 `export` 를 넣어
  `source` 한 셸의 자식 프로세스도 값을 본다.
- `env.sh` 가 없을 때의 안내를 고쳤다. 이전에는 무조건 `00-env.sh` 로 보냈는데, 킷 교체 상황에서는
  그것이 바로 기준선을 옮기는 길이었다.
- 런북에 "새 터미널마다 `source`" 를 첫 줄로 명시.

## 7차에서 달라진 것

- `run/00b-resume.sh` 신설(어디서부터 이어서 할지 찍는 읽기 전용 점검).
- 2·3단계 재실행 안내 수정. 2단계가 *"출발 태그 이름을 새로 바꿔라"* 라고 안내해 기준선을 옮길 뻔했다.
- 런북에 **"njh-cli 는 어디에 쓰나"** 표 — 단계별로 무엇을 시키고 **무엇이 그 결과를 판정하는지**.
- 의존성 대조 도구에 읽기 전용 `--check` 추가.

## 6차에서 달라진 것

- **초안 빌드가 통과한다.** 변환 여럿이 한쪽 실행 경로에만 배선돼 있어 실제 프로젝트가 타는 경로에서
  빌드가 깨지고 완전 전환이 0으로 집계됐다. 배선 12종을 채우고 **두 실행 경로가 같은 변환을 타는지
  검사하는 계약 테스트**를 넣었다. 앞으로 배선이 빠지면 빌드가 아니라 테스트가 먼저 깨진다.
- **공통 부품이 전부 착지한다.** 채택하는 화면이 없어 파일 자체가 안 깔리던 부품 8종을 정본 경로에
  직접 넣는다(화면은 건드리지 않는다). 다른 설치자가 주인인 경로는 덮어쓰지 않고 거부로 기록한다.
- **게시 단계 합격 관문 3개** — `npm run build` · `npm run serve` 기동 응답 · **공통 부품 착지 검사**.
- **새 단계 4개**
  - `run/05a-ai-repair.sh` — 빌드가 막히면 CLI 에이전트가 차단 파일을 하나씩 보수한다. 기능을 지워
    통과시킨 수정은 스크립트가 되돌린다(대상 외 파일 변경도 되돌린다).
  - `run/08a-login-session.sh` — 담당자가 브라우저에서 직접 로그인한다. 아이디·비밀번호는 킷도 스크립트도 받지 않는다.
  - `run/08b-route-sweep.sh` — **실제 브라우저로 라우트를 하나씩 열어 화면이 뜨는지 잰다.** 빌드 통과와
    서버 응답은 화면이 살아 있다는 증거가 아니기 때문이다. 브라우저는 내려받지 않고 이미 깔린 Edge/Chrome 을
    쓰며, 순회 중 GET/HEAD 외의 요청은 차단한다.
  - `run/08c-screen-repair.sh` — 안 뜨는 화면을 하나씩 보수하고 **다시 재서** 실제로 떴는지 확인한다.
    끝내 안 뜨는 화면은 `화면-담당자-배정.md` 로 나온다.
