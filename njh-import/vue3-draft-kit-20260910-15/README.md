# Vue 3 초안 킷 — 15차 (DRAFT_REGISTRY_CHANGED 근본 수정)

```bash
sha256sum -c sha256.txt
7z x -p'<암호>' vue3-draft-kit-20260910-15.7z
source "<15차 킷 경로>/kit.sh"
bash "$KIT/run/00b-resume.sh"
```

## 14차에서 고친 것 — 이게 핵심이다

사내 실행에서 초안이 `DRAFT_REFUSED / DRAFT_REGISTRY_CHANGED` 로 거부됐다.
**옛 킷으로 만든 초안 디렉터리가 그대로 남아 있었고, 새 킷은 스테이지 구성이 달라
드라이버가 섞느니 거부한 것이다**(드라이버 판단은 옳다).

문제는 `05-draft.sh` 가 그 옛 초안을 옆으로 치우지 못한 것이었다. 치우는 조건이
"영수증의 `skillTip` 이 다르면" 인데 **그 영수증에 `skillTip` 이 없어서** 조건이 조용히
실패했다. 그래서 낡은 초안 위에서 새 킷이 돌았다.

그 결과 화면 스테이지까지 가지 못해 **킷이 자동으로 고칠 수 있는 것들**(닫히지 않은 `</tr>`,
0바이트 빈 SFC, 짝 없는 CSS 주석 종료자)이 전부 손작업으로 넘어갔다.

- `05-draft.sh` 가 **어느 킷으로 만든 초안인지 직접 도장(`.kit-tip`)을 남긴다.** 영수증 필드에
  기대지 않으므로 조용히 실패하지 않는다.
- 그래도 `DRAFT_REGISTRY_CHANGED` · `DRAFT_SOURCE_CHANGED` · `DRAFT_CONSUMER_DIVERGED` 로
  거부되면 **옛 초안을 `$DRAFT-stale-<시각>` 으로 옮기고 한 번만 자동으로 다시 만든다.**
  손댄 내용은 그 디렉터리에 그대로 남는다.
- 기준선 커밋에 `.gitattributes (* -text)` 를 넣어 Windows 의 줄바꿈 변환이 기준선의
  바이트 기준을 흔들지 않게 했다.
- `00b-resume.sh` 도 도장을 먼저 읽는다(이전에는 `옛 킷(?)` 으로만 보였다).

## 14차에 들어간 것

- 초안이 git 으로 추적된다. 5단계가 생성 직후를 기준선으로 커밋하므로 이후 보수가 전부
  `git -C "$DRAFT" diff` 로 보인다. **AI 가 기능을 지웠는지 눈으로 확인하는 수단이다.**

## 이미 손으로 고쳐 둔 초안이 있다면

15차의 5단계는 그 초안을 **지우지 않고** `$DRAFT-stale-<시각>` 으로 옮긴 뒤 새로 만든다.
새 초안에서는 위 세 가지가 코드모드로 자동 처리되므로, 옮겨 둔 쪽과 비교해 보고
정말 필요한 손작업만 다시 옮기면 된다.
