## 이 키트가 담는 것

- v1.5.550(같은 날 오전 키트)의 내용 전체 — 터미널 UI 4라운드 5요소와 게이트 수정 — 에 더해, 사내 Codi 공통 모델로 바로 테스트할 때 부딪히는 두 가지를 고쳤습니다(소스 기준 v1.5.550 → v1.5.551 누적 통합). v1.5.550 을 아직 설치하지 않았다면 이 키트만 설치하면 됩니다.
- 구성은 이전 정식 키트와 동일합니다: 클라이언트(njh-cli), 게이트웨이(njh-gateway), 노트북 검증 킷(njh-win-laptop), Ollama Windows CPU 런타임, OCR 엔진, 빌드 매니페스트, SHA-256 매니페스트.
- 설치 절차와 현장값 관리 방식은 바뀌지 않았습니다. 현장값은 `~/.njh-cli/site.env` 한 파일에만 두고, 설치 명령은 용량 확인 → 전체 사전 점검 → 실제 설치 순서를 그대로 따릅니다. 앞 단계가 실패하면 다음 단계로 넘어가지 않습니다.

## 수신자 관점의 주요 변화

- **사고 모드 출력 걸러내기**: Codi 앱의 "사고 모드"가 켜져 있으면 모델이 답변 앞에 `<think>…</think>` 사고 블록을 흘려보낼 수 있습니다. 이제 클라이언트가 그 블록을 화면에 그리지 않고, 누적 답변에 넣지 않으며, 사고 안에 적힌 도구 호출 JSON 을 실제 호출로 오인하지 않습니다. 태그가 스트리밍 청크 경계에서 갈려 도착해도 안전하며, 닫히지 않은 사고 블록은 답변 종료 시 버립니다.
- **질문 열 때 실패한 초안 복원**: 전송이 실패한 입력 초안이 다음 질문(readline)이 열리는 시점에 동기적으로 복원되어, 재입력 없이 이어서 편집할 수 있습니다.
- v1.5.550 의 변화(위험 심각도 토큰 통일, 도구 활동 행의 의도 요약·수치 우선 결과, 개인정보 가림 표시 규약, 컴포저·상태 표시줄 정합, 서브에이전트 완료 접기와 인라인 탐색, 게이트 결함 근본 수정)는 그대로 포함됩니다. 자세한 설명은 `릴리스노트-v1.5.550.md`를 참고하십시오.

## DevAI(OpenCode 기반)와의 동일 모델 비교 절차

사내 Codi에는 DevAI와 njh-cli가 함께 쓸 수 있는 공통 모델 `[KTDS] Qwen3.8-Flash-Next`(262k 컨텍스트)가 있습니다. 두 도구를 같은 모델·같은 과제로 비교할 때는 다음을 지키십시오.

1. njh-cli용 Codi 앱은 **사고 모드를 끄고**, 창의성(temperature)은 0.2 안팎, 최소 출력 토큰은 1로 두십시오. 이 키트부터는 사고 모드가 켜져 있어도 사고 블록이 걸러지지만, 사고 토큰만큼 응답이 느려지므로 비교 측정에서는 끄는 편이 공정합니다.
2. 같은 Vue 3 마이그레이션 과제 3~5개(예: 필터 제거, 이벤트 리스너 API 교체, 비동기 컴포넌트 선언)를 두 도구에 **같은 문장으로** 입력하고, 시간 제한을 두지 마십시오. 120초 같은 짧은 예산은 결과를 뒤집는 교란 변수임이 확인되었습니다.
3. 판정은 결과물의 빌드·테스트 통과 여부와 원본 소스 줄 손실 여부로 하고, 화면은 도구별로 캡처해 함께 보관하십시오. 화면 캡처는 `docs/사용자/06-post-import-first-30-minutes.md`의 증빙 보관 규칙을 따릅니다.
