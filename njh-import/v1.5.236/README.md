## ⚠️ CLI 킷을 반드시 교체하세요 (v1.5.226 → v1.5.236)

v1.5.219~235 동안 안내에 "CLI 킷은 v1.5.226 폴더 그대로"라고 적혀 있었는데,
**그 사이 v1.5.228 에서 njh 런타임이 바뀌었습니다.** 잘못된 안내였습니다.

무엇이 바뀌었나: njh 가 `settings.json` 의 `connection.local.numBatch` 를 읽어
**로컬 모델이 상주 중인 것과 똑같은 적재 옵션으로** 요청하도록 배선했습니다.

v1.5.226 을 쓰면 이렇게 됩니다:
1. `start-local-llm.sh` 가 모델을 `num_batch=256` 으로 GPU 에 올림 (정상)
2. njh v1.5.226 은 `num_batch` 개념이 없어 **그 옵션 없이** 요청
3. ollama 는 적재 옵션이 하나라도 다르면 모델을 **통째로 다시 적재**
4. 그 재적재가 CPU 로 착지 → 작업관리자의 GPU 메모리가 뚝 떨어짐

즉 "호출테스트 치자마자 CPU 100%" 는 부하 문제가 아니라 **버전 불일치**였습니다.

## 설치 순서

```bash
# 1) CLI 킷을 기존 njh 설치 위치에 풀고 설치 (기존 방식 그대로)
#    ※ 예전 v1.5.226 폴더로 njh 를 실행하지 마세요. PATH 도 새 위치로.
# 2) 노트북 로컬 LLM 도구
cd /c/njh-local-llm
./setup-local-llm.sh      # 필요 시 (이미 튜닝했으면 생략 가능)
./start-local-llm.sh      # GPU 상주
# 3) njh 실행 → 호출테스트
ollama.exe ps             # PROCESSOR 가 GPU 로 유지되는지 확인
```

버전 확인: njh 시작 화면 오른쪽 위가 **v1.5.236** 이어야 합니다.

## 게이트웨이 (AP03, 선택)

모니터의 "경과"가 0 → 4초 → 0 으로 되돌아가던 문제를 고쳤습니다. 재라우팅 때마다
시작 시각이 초기화되던 것이 원인이었습니다. `stop.sh` → 압축 해제 → `start.sh`.
