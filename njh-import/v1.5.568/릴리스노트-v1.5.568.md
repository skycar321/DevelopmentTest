## 이 키트가 담는 것

- v1.5.567(전 키트)의 기능 전체에 더해, 아래 변경이 들어갔습니다. 구성은 이전 정식 키트와 동일합니다: 클라이언트(njh-cli), 게이트웨이(njh-gateway), 노트북 검증 킷(njh-win-laptop), Ollama Windows CPU 런타임, OCR 엔진, 빌드 매니페스트, SHA-256 매니페스트.
- 설치 절차와 현장값 관리 방식은 바뀌지 않았습니다. 현장값은 `~/.njh-cli/site.env` 한 파일에만 두고, 설치 명령은 용량 확인 → 전체 사전 점검 → 실제 설치 순서를 그대로 따릅니다.

## 수신자 관점의 주요 변화

- **진행 표시 겹침 수정이 실제로 그 증상을 고친다는 것을 재현으로 확인했습니다**: 이전 버전에서는 줄바꿈 없이 끝난 출력 뒤에 진행 표시가 같은 줄에 이어 써져 `모델 첫 응답 8.3sQwen3.8-…` 처럼 글자가 붙었고, 이번 버전에서는 그 경우 되살리기를 건너뜁니다. 재현 결과(이전 1건 / 현재 0건)를 테스트에 수치로 고정해, 다음에 같은 결함이 생기면 테스트가 먼저 잡습니다.
- **고정 상태줄이 켜지는 터미널 확인**: `njh --debug-sticky` 가 `ui=auto->full` 인지 `conservative` 인지 한 줄로 알려 줍니다. Windows Terminal(Git Bash 프로필 포함)은 `full` 로 해석되어 상단 고정 헤더와 하단 상태줄이 켜집니다. 단독 Git Bash(mintty)와 VS Code 통합 터미널은 `conservative` 로 남습니다 — 두 경우 모두 창 크기를 신뢰할 수 없거나 IDE 가 화면을 따로 관리해, 절대좌표로 그리면 사용자 출력을 지울 수 있기 때문입니다. 이때는 인라인 헤더 배너가 대신 나옵니다.

## 서버에서 돌리기 전에

- Node.js 요건은 `22.13.0+` 로 변함이 없습니다. 분리 미션·`/goal` 운용 절차는 `서버-운영-가이드.md` 가 정본이고, 미션이 커밋까지 하게 하려면 `미션-git-쓰기-정책.md` 의 두 스위치를 모두 켜야 합니다.
- 키는 환경 변수에만 넣고 설정 파일에는 환경 변수의 이름만 둡니다. 키 값, 호스트, 조직명은 문서·로그·설정 파일에 기록하지 않습니다.

## 설치 전에 확인할 것

- 이전 키트에서 안내한 사전 점검·보관·거부 규칙이 그대로 적용됩니다. 처음 설치하거나 절차가 기억나지 않으면 키트에 동봉된 `통합-설치가이드`와 `02-설치-및-업데이트` 문서를 먼저 읽으십시오.
- 기존 서비스 디렉터리는 삭제하거나 덮어쓰지 않고 시각이 붙은 형제 디렉터리로 보존되며, Ollama 모델 저장소는 그대로 유지됩니다.
