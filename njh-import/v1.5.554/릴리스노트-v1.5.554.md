## 이 키트가 담는 것

- v1.5.553(전 키트)의 화면 표기 통일·업로드 오류 안내·OCR 적재 스키마 전체에 더해, **사내 OpenAI 호환 서버 연결, 상시 목표(`/goal`)와 분리 미션(`njh mission`), 무인 실행 승인 계약, 서브에이전트 역할 프로필과 공유 동시성 상한, 동아시아 로캘 화면 폭 보정**이 들어갔습니다. v1.5.553을 아직 설치하지 않았다면 이 키트만 설치하면 됩니다.
- 구성은 이전 정식 키트와 동일합니다: 클라이언트(njh-cli), 게이트웨이(njh-gateway), 노트북 검증 킷(njh-win-laptop), Ollama Windows CPU 런타임, OCR 엔진, 빌드 매니페스트, SHA-256 매니페스트.
- 설치 절차와 현장값 관리 방식은 바뀌지 않았습니다. 현장값은 `~/.njh-cli/site.env` 한 파일에만 두고, 설치 명령은 용량 확인 → 전체 사전 점검 → 실제 설치 순서를 그대로 따릅니다.
- 클라이언트 문서에 `서버-운영-가이드.md`, `OpenAI-서버-전송.md`, `사내-OpenAI-호환-첫-실행-검증.md` 세 문서가 새로 동봉되었습니다. 서버에서 무인으로 돌리는 절차와 사내 OpenAI 호환 연결의 첫 실행 판정 기준은 이 세 문서가 정본입니다.

## 수신자 관점의 주요 변화

- **DevAI 발급 키 하나로 사내 OpenAI 호환 서버에 연결합니다.** 설정에서 `connection.active: "openai-import"` 를 고르고 그 프로필의 `apiBaseUrl` 을 채운 뒤, 키는 환경 변수 `NJH_OPENAI_CHAT_KEY` 로만 넣습니다. 출하 설정의 `model` 은 자리표시자이므로 발급받은 모델 ID를 대괄호·공백 그대로 채웁니다(현재 발급 모델: `[KTDS] Qwen3.8-Flash-Next`). DevAI·opencode 바이너리, tmux, screen, systemd, GPU 는 필요하지 않습니다. `openai` 로 시작하는 프로필은 Codi 의 Dify `chat-messages` 경로로 **되돌아가지 않으며**, 네이티브 전송이 불가능하면 조용히 다른 경로를 타는 대신 `TRANSPORT_UNAVAILABLE` 로 실패를 알립니다. `njh doctor --json` 의 `transport` 절에서 활성 프로필·URL·모델과 실제 1회 요청 결과를 확인할 수 있습니다.
- **상시 목표(`/goal`)를 세션 안에서 돌립니다.** `/goal <목표> --max-iter N --name X` 로 목표를 저장하고 같은 도구·모델·권한으로 반복 수행합니다. 상태줄에 `Pursuing goal (경과) · iter k/N` 이 보이고, 완료는 모델이 "done" 이라고 말한 것이 아니라 정확한 `GOAL_DONE` 토큰과 런타임 완료 게이트 검증이 함께 있어야 `Goal achieved` 가 됩니다. 반복 상한에 닿으면 성공을 선언하지 않고 멈춥니다(`Goal stalled (max_iter)`). ESC 또는 Ctrl+C 한 번으로 일시정지합니다.
- **분리 미션(`njh mission`)은 SSH 가 끊겨도 계속 돕니다.** `njh mission start --name m1 --goal "…" --max-iter 5` 로 시작하면 같은 CLI 번들이 분리 실행기로 계속 돌고, 다시 접속한 뒤 `njh mission list`, `njh mission status m1 --json`, `njh mission log m1`, `njh mission resume m1`, `njh mission stop m1` 로 상태·로그·목표를 조회하고 이어갑니다. TUI 에서 진행 중인 목표는 `/goal detach` 로 분리 실행기에 넘기고 TUI 를 종료해도 됩니다. 재진입은 **상태·로그·목표가 계속 조회된다**는 뜻이며 tmux 식 라이브 재접속은 아닙니다. 상한·차단·예산 소진으로 멈춘 미션은 종료 코드 **2** 로 끝나므로 프로세스가 끝났다고 작업이 끝난 것으로 보지 마십시오.
- **무인 실행의 승인 계약이 명확해졌습니다.** `njh -p "요청" --output-format json` 이 승인이 필요한 도구를 만나면 모델에게 재시도를 시키지 않고 종료 코드 **2** 와 `stop_reason: "approval_unavailable"` 로 멈춥니다. 응답에는 거부된 도구와 명시적 허용 방법(`-y`, 즉 `--dangerously-skip-permissions`, 또는 허용하는 실행 정책 프리셋)이 적혀 있습니다. 정책으로 거부된 도구는 그대로 거부됩니다.
- **서브에이전트 역할 프로필과 공유 동시성 상한이 들어갔습니다.** `.claude/agents/` 에 `implementer`, `reviewer`, `devils-advocate`, `consolidator` 프로필이 동봉되어 구현·검토·반박·취합을 역할별로 위임할 수 있습니다. 동시에 도는 서브에이전트 수는 `subAgents.maxConcurrency`(기본 2, 1–16 범위로 보정) 하나로 제한되며, 예전 `subAgents.claudeStyle.maxConcurrency` 만 있으면 그 값을 그대로 씁니다. 워크플로·합의 요청도 같은 세마포어를 타므로 합산 동시 요청 수가 상한을 넘지 않습니다.
- **한국어·일본어·중국어 로캘에서 상태줄이 깨지지 않습니다.** `…`, `▮` 같은 모호폭 기호를 로캘에 따라 2칸으로 계산하고, `NJH_AMBIGUOUS_WIDTH=wide|narrow` 로 강제할 수 있습니다. 좁은 폭에서는 완료 행의 사실(도구·대상·시간·승인·정책)을 자르지 않고 덜 중요한 힌트를 통째로 뺍니다.
- **Codi 연결의 네이티브 경로 폴백을 화면에 알립니다.** Codi 연결에서 네이티브 도구 경로가 일반 404 를 돌려주면 Dify 경로로 넘어가며 그 사실을 알립니다(OpenAI 프로필에는 해당하지 않습니다). 컨텍스트 한도로 재시도할 때는 긴 도구 결과를 압축해 다시 보내고, 첨부 인라인 재시도 뒤에도 대화 기록이 실제 전송 내용과 같게 유지됩니다.

## 서버에서 돌리기 전에

- Node.js 요건은 `22.13.0+` 입니다. `서버-운영-가이드.md` 의 절차는 tmux·screen·systemd 없이 분리 실행기만으로 동작합니다.
- 키는 환경 변수에만 넣고 설정 파일에는 환경 변수의 이름만 둡니다. 키 값, 호스트, 조직명은 문서·로그·설정 파일에 기록하지 않습니다.
- 분리 미션에 후속 지시를 보내려면 `njh agents reply mission:m1 --message "…" --dir <미션 상태 디렉터리>` 와 `njh agents wake mission:m1 --dir <미션 상태 디렉터리>` 를 씁니다. `delivered:false` 는 큐에 들어갔다는 뜻이며 전달 완료가 아닙니다.

## 설치 전에 확인할 것

- 이전 키트에서 안내한 사전 점검·보관·거부 규칙이 그대로 적용됩니다. 처음 설치하거나 절차가 기억나지 않으면 키트에 동봉된 `통합-설치가이드`와 `02-설치-및-업데이트` 문서를 먼저 읽으십시오.
- `02-설치-및-업데이트.md`와 `06-post-import-first-30-minutes.md`의 `CAPACITY REFUSE` 대응 절차(재시작 금지, 출력 수치로 모델·컨텍스트·JVM 배치 조정 후 재실행)는 v1.5.553과 동일하게 유지됩니다.
- 기존 서비스 디렉터리는 삭제하거나 덮어쓰지 않고 시각이 붙은 형제 디렉터리로 보존되며, Ollama 모델 저장소는 그대로 유지됩니다.
