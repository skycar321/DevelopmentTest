## 이번 버전 내용

**1. 채택 기준 = 실사용 최대 부하 생존**
njh 는 컨텍스트를 꽉 채워 요청할 수 있으므로, 각 후보를 **ctx의 92%를 채운
프롬프트**(njh 와 같은 /api/chat + 도구 정의)로 검증합니다. 중간 크기만 통과한
조합은 채택하지 않습니다 — 그게 지금까지 "튜닝은 통과, 실사용은 낙하"가 반복된
이유였습니다.

**2. CPU 로 떨어지면 즉시 다음 후보로**
15초마다 GPU 상주를 확인해 이탈하는 순간 요청을 끊습니다(기다려봐야 CPU 속도로
수십 분). `/api/ps` 무응답은 낙하로 보지 않고, 2회 연속 확인될 때만 버립니다.

**3. GPU 가 전부 안 되면 CPU 안에서 최적을 찾습니다**
스레드 수(물리/논리)와 KV 양자화를 실제로 비교해 가장 빠른 조합을 채택하고,
판정·settings.json·환경변수까지 그 값으로 맞춥니다. "CPU 가 정답"으로 끝내지
않습니다.

**4. 우선순위** = GPU > CPU → 컨텍스트 큰 쪽 → 빠른 쪽.
빨리 끝내려면 `NJH_TUNE_FAST=1 bash tune-gpu-ctx.sh` (첫 통과에서 중단).
