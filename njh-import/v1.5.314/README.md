## 0. 먼저 받은 파일이 맞는지 확인 (풀기 전)

```bash
shasum -a 256 njh-cli-v1.5.314.7z njh-gateway-v1.5.314.7z njh-win-laptop-v1.5.314.7z
# sha256sum 이 있으면 그것도 됩니다
```

`SHA256SUMS.txt` 의 값과 **한 글자라도 다르면 풀지 말고 다시 받으십시오.**

## 1. 설치

```bash
# CLI 킷 (모든 사람)
7z x njh-cli-v1.5.314.7z -o"$HOME/njh-cli-v1.5.314"
cd "$HOME/njh-cli-v1.5.314"
bash setup.sh
"$HOME/.njh-cli/bin/njh" --version     # → 1.5.314 가 찍혀야 합니다

# 노트북 로컬 LLM 도구
cd /c/njh-local-llm
./verify-local-llm.sh      # ← 먼저 이것부터
./start-local-llm.sh
njh                        # 호출테스트
ollama.exe ps              # PROCESSOR 가 GPU 로 유지되면 끝

# 게이트웨이 담당자만
njh onboard gateway && bash "$HOME/.njh-cli/scripts/njh-connect-doctor.sh"
```

⚠️ **예전 버전 폴더의 `njh` 는 쓰지 마세요.** PATH 도 새 위치를 보게 하십시오.
버전이 섞이면 로컬 LLM 이 적재 옵션 불일치로 **모델을 통째로 재적재**하고, 그 재적재가
GPU 가 아니라 CPU 로 착지합니다. (v1.5.238 안내에서 짚었던 그 문제입니다.)

## 2. v1.5.238 이후 달라진 것 중 받는 쪽에 영향이 있는 것

**게이트웨이**
- 모델 워밍업 프로브에 상한이 생겼습니다. 워밍업이 라우팅을 잡아먹지 않습니다.
- 타임아웃 난 모델 요청을 격리합니다. 한 건이 늦어도 뒤 요청이 같이 밀리지 않습니다.
- 배포 대상 클라이언트 대역(CIDR)이 설정값이 되었습니다. 재빌드 없이 바꿉니다.

**패키징·안전성**
- 킷 3종을 한 번에 검증하는 **safety gate** 가 생겼습니다. 이번 업로드분은 3종 모두 `pass` 입니다.
- 누출 스캐너가 **번들 안의 압축된 페이로드까지 펼쳐서** 검사합니다. 예전에는 번들 바깥만 봤습니다.
  이번 킷 3종의 누출 적발은 **0건**입니다.
- 개발 머신의 절대경로가 문서에서 제거됐습니다. 받는 쪽에서 실행 가능한 경로만 남습니다.

**스킬**
- 저사양 프로파일 페이로드를 줄였습니다. 약한 노트북에서 스킬이 컨텍스트를 덜 먹습니다.

## 3. 이 킷으로 증명된 것과 증명되지 않은 것 (그대로 옮깁니다)

**증명됨** — 아카이브에서 CLI 를 실제로 꺼내 실행했고 `1.5.314` 를 출력합니다.
파일 목록 319개, 압축 해제 34.7 MB, 매니페스트·제외규칙·런처/설치기 검증 통과.

**증명되지 않음 — 사내망에서만 확인 가능합니다.**
인증된 Codi 호출, 사내 SQMS 조회, 게이트웨이 3대 함대 수용 시험은 **여기서 관측된 적이 없습니다.**
붙지 않으면 그것은 `BLOCKED_INTERNAL_NETWORK` 이지 PASS 가 아닙니다. 그렇게 기록해 주십시오.

**리허설 기준선은 v1.5.307 입니다.** 패키지 안의 인수 문서(`handoff-docs/`)에 적힌 실측 근거는
v1.5.307 세트에서 나왔습니다. v1.5.314 는 그 위에 게이트웨이·패키징 수정이 얹힌 것으로,
**새로 빌드하고 안전 게이트를 통과했지만 v1.5.307 과 같은 전체 리허설을 다시 돌리지는 않았습니다.**
실행 실패가 나오면 v1.5.307 의 증거를 그대로 적용하지 말고 **첫 실패 출력을 보존해서 알려주십시오.**
