## 4. 이번 판 변경 (사용자 지적 반영)

| # | 지적 | 조치 |
|---|---|---|
| 1 | 실행주기가 빌더 위쪽(cron)과 고급 연동·배포(schedule) 두 곳에 있어 왜 두 개인지 알 수 없음 | 같은 설정이 맞습니다(위=`schedules` 복수 키, 고급=옛 `schedule` 단수 키). 고급 쪽을 **`단일 실행주기 (schedule · 옛 형식)`** 로 바꾸고 "위 「실행주기 규칙(cron)」과 같은 설정이며 위에서 편집했다면 여기는 비워 둡니다" 를 설명에 명시 |
| 2 | 상세 모달의 **맞춤** 버튼 CSS 깨짐 | 스타일이 `.airflow-content` 하위로만 걸려 있어 모달에서 기본 버튼으로 떨어진 것. 모달 스코프 추가 (같은 툴바 `실패 시뮬` 은 스코프가 없어 멀쩡했음) |
| 3 | `실행 허가 요청` → **`실행 요청`** | 목록 헤더·버튼·확인 대화상자·투어 문구까지 전량 통일 (승인 화면·가이드가 이미 쓰던 용어) |
| 4 | `실행주기 변경` → **`스케줄 변경`** | 동일하게 전량 통일 |
| 5-1 | 목록에 `multi-cron:` 개발자 용어 노출 | 표시에서만 접두어 제거(`multi-cron: 0 2 * * *` → `0 2 * * *`). **쉼표 목록은 쪼개지 않습니다** — 요일 목록(`1-5,7`) 오분할을 막기 위해 원본 형태를 그대로 유지 |
| 5-2 | 탭은 `실행 순서 그림`, 안쪽 제목은 `작업 흐름도` 로 두 이름 | **`작업 흐름도`** 로 통일 |

### 함께 고친 것 — 멀티크론 배치의 스케줄을 화면에서 바꿀 수 없던 문제

여러 실행주기를 쓰는 배치(예: `30 2 * * 1-5,7, 0 9 * * 6`)는 **스케줄 변경 창을 열자마자
"cron 표현식이 5필드가 아닙니다" 로 막혀 요청 버튼이 잠겼습니다.** 검증과 제출이 같은 값을
서로 다르게 해석하고 있었습니다. 검증을 제출과 같은 해석으로 맞춰 정상 통과하도록 고쳤습니다.

- 실측: 창을 열면 `✓ 사용 가능한 실행주기입니다 / 유형: multicron` 과 다음 실행 3건이 표시되고 요청 버튼이 열립니다.
- 일괄(여러 배치 한 번에) 변경은 서버가 배치당 하나의 실행주기만 받으므로, **여러 실행주기를 쓰는 배치는 각 행의 `스케줄 변경`** 에서 바꿔 주세요. 일괄 화면 안내문도 그렇게 고쳤습니다.
- `dataset(...)` 스케줄과 `@daily` 같은 프리셋은 이 변환에서 제외되어 영향받지 않습니다.
