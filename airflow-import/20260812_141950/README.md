## 검증 상태

- **패키징 검증 `verify_bundle` 24 PASS / 0 FAIL** (변수 게이트·제외 정책·shipped shell `bash -n` 포함).
- 정본 화면 스위트를 이 판으로 실행한 결과는 **44 PASS / 5 FAIL / 1 HOLD** 입니다. 직전 판은 34 PASS 였고, 통합으로 스위트가 도는 게이트 자체가 34개에서 50개로 늘었습니다.

실패 5건은 통합이 드러낸 것이며, 원인을 특정했습니다. **3건은 같은 뿌리**입니다.

사진 피드백에서 "물음표가 다 붙어 있어 읽기 힘들다"고 하신 지적에 따라 빌더의 물음표 도움말을 접었습니다. 그런데 그 물음표를 셀렉터로 찾던 게이트 3개가 제품 변경과 같은 시점에 옮겨지지 않아, 통합 시점에 한꺼번에 터졌습니다.

| 실패 게이트 | 내용 | 성격 |
|---|---|---|
| `builder-help-focusout-repeated-controlled-owner` | `id 설명` 물음표를 못 찾아 실행 단계에서 중단 | 게이트가 옛 표면을 봄 |
| `builder-retry-focus-adversarial` | 같은 뿌리. 사유 문자열 없이 종료코드만 비정상 | 게이트가 옛 표면을 봄 |
| `behavioral-a11y-r12-smoke` | DAG ID 도움말의 `aria-describedby` 연결이 null | 게이트가 옛 표면을 봄 |
| `visual-geometry-sweep` | 데스크톱 전용 스타일 정책에서 1024px 미만 규칙 2건이 남아 있음 | **실제 미완 작업** |
| `e0728-screen-walk-suite-safe` | 도움말 투어 내용 화면의 단언 미충족 | 원인 분리 중 |

**앞의 3건은 화면 동작 결함이 아닙니다** — 제품은 요청하신 방향대로 바뀌었고, 그것을 재던 검사가 옛 위치를 보고 있습니다. 검사를 새 도움말 표면(인라인 설명 문구 + 화면낭독기용 설명 + `aria-describedby` 연결)으로 옮기는 작업을 배정했습니다. 다만 옮기면서 느슨하게 만들지 않도록, 새 설명 문구를 지운 반례에서 반드시 실패하는 것까지 확인하게 했습니다.

뒤의 2건 중 `visual-geometry-sweep` 은 실제로 손대야 할 CSS 규칙 2건이 남아 있는 것이고, `screen-walk` 는 어느 단언이 왜 깨졌는지 분리 중입니다. 둘 다 이번 판 반입 범위의 화면 동작에는 영향이 없습니다.
