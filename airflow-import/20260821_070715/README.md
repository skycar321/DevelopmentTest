### 1. DB 스키마를 손으로 한 번 적용해야 합니다

`deploy.sh` 는 SQL 을 적용하지 않습니다. 배치어드민 재배포 **전에** 아래를 실행하세요.

```bash
psql -v ON_ERROR_STOP=1 -h <배치어드민 DB host> -U <user> -d <db> \
  -f batch-admin-reference/sql/airflow_control_ddl.sql
```

- `-v ON_ERROR_STOP=1` 을 **반드시** 주세요. psql 기본값은 중간 문장이 실패해도 계속 진행하고
  **종료코드 0** 으로 끝납니다. 그대로 두면 실패를 성공으로 읽습니다.
- `BEGIN … COMMIT` 으로 감싸지 마세요. 인덱스를 `CREATE INDEX CONCURRENTLY` 로 만드는데
  트랜잭션 안에서는 돌지 않습니다.
- 이미 적용해 본 환경도 **이번 판에는 다시 실행**해야 합니다. 안 하면 화면은 뜨지만
  실행요청·활성화요청·일괄요청·매니페스트 수정이 `column "idempotency_scope" does not exist` 로
  실패합니다.
- 파일 끝 검증 블록이 예외를 던지면 **적용이 안 끝난 것**입니다. 메시지의 조치를 하고 다시 적용하세요.
- 운영 테이블에 오래 걸리지 않도록 컬럼 추가는 한 문장으로 합쳤고 `lock_timeout 3s` 를 걸었습니다.
  잠금 대기로 실패하면 한가한 시간에 같은 파일을 다시 적용하면 됩니다(멱등).

## 이 판에서 고쳐진 것 — 실제로 겪던 문제들

### 승인한 실행과 취소가 **둘 다 성공**으로 보고될 수 있었습니다

같은 승인 요청에 실행과 취소가 겹치면, 실행 청구는 부모 행만 잠그고 취소는 자식 행까지
잠가서 서로를 막지 못했습니다. 두 요청이 각자 자기 작업을 완료로 보고할 수 있었습니다.
두 처리가 같은 행들을 함께 잠그도록 맞췄고, 두 접속이 실제로 경합하는 회귀 시험을 넣었습니다.

### 화면에 보이는 **한글 작업 단계**를 골랐는데 서버가 거부했습니다

목록 화면은 Airflow 가 돌려준 작업 단계 이름을 그대로 범위 실행 드롭다운에 넣는데,
서버 검증만 영문·숫자로 제한돼 있었습니다. 배치 이름(DAG ID)은 이미 한글을 허용하고 있었으니
같은 기준으로 맞췄습니다. 경로 구분자·공백은 여전히 거부합니다.

### 한글 배치 이름에서 **정지·관리 요청이 막혔습니다**

중복 요청 방지용 키에 배치 이름·실행 ID·작업 단계가 들어가 있었습니다. 한글 이름은 인코딩되면
글자당 9자로 늘어나, 이름이 조금만 길어도 서버의 200자 상한을 넘겨 요청이 거부됐습니다.
키에서 사용자 입력을 전부 뺐습니다(중복 방지는 무작위 값이 담당합니다).

### 같은 요청을 다시 보냈을 때 **새 내용이 조용히 사라질 수 있었습니다**

24시간이 지난 중복 방지 기록을 다른 요청이 먼저 정리해 버리면, 같은 키로 다시 보낸 요청이
예전 실행을 그대로 재사용하고 새 내용은 반영되지 않았습니다. 화면에는 정상 접수로 보였습니다.
정리 대상에서 해당 기록을 제외해 이 경로를 막았습니다.

### 환경별 설정 화면에서 **조회가 실패해도 저장이 열려 있었습니다**

서버 상태를 못 읽은 채로 저장을 누를 수 있었습니다. 이제 조회에 실패하면 저장은 잠긴 채로
두고, 그 자리에서 다시 시도할 수 있게 했습니다.
