## 4. 이번 판 변경 — 실제로 고친 것 넷

### 4-1. `dataset(...)` 스케줄이 제출 과정에서 쪼개지던 결함 ★

스케줄 변경 창에서 **검증은 통과하는데 저장되는 값이 달라지는** 문제가 있었습니다.

`dataset('a', 'b')` 처럼 **괄호 안에 쉼표가 있는** 스케줄을 제출하면, 제출 경로가 그 쉼표를
멀티크론 구분자로 착각해 `dataset('a'` 와 `'b')` 두 조각으로 쪼갰습니다. 검증 경로는
쪼개지 않고 원본을 보는데 제출 경로만 쪼개서, **검증에서 본 값과 저장되는 값이 서로 달랐습니다.**

검증과 제출이 **같은 함수로 같은 판단**을 하도록 합쳤습니다. 이제 `dataset(...)`·`asset(...)`,
`@daily` 같은 프리셋, `[` 로 시작하는 구조 표현은 어느 경로에서도 쪼개지지 않습니다.
평범한 멀티크론(`30 2 * * 1-5,7, 0 9 * * 6`)은 종전대로 쪼개집니다.

### 4-2. 배포 `[4c/5]` 단계의 결함 셋

직전 판에서 넣은 "자동 변환 뒤 로더를 한 번 더 스캐폴딩하는" `[4c/5]` 단계에 결함이 셋 있었습니다.

| 결함 | 증상 |
|---|---|
| 실패 분기 도달 불가 | 스캐폴딩이 실패해도 그 rc 가 파이프에 먹혀 **항상 성공으로 읽혔습니다** |
| dry-run 무정보 | dry-run 이라면서 실제로는 `--dry-run` 을 붙이지 않아 결과를 알 수 없었습니다 |
| 실패 무전파 | 실패해도 배포 마지막 Integration status 에 아무 흔적이 남지 않았습니다 |

셋 다 고쳤습니다. 이제 `[4c/5]` 가 실패하면 `LOADER_2ND_STATUS` 로 배포 요약에 드러납니다.

### 4-3. 투어 말풍선 아래 빈 네모 + `입장` → `역할`

사진으로 지적하신 두 건입니다.

- **여러 화면에 보이던 알 수 없는 네모 박스**: 투어 말풍선의 "이 단계 위치로" 버튼이
  숨김 상태인데도 인라인 스타일 때문에 계속 그려지고 있었습니다. 인라인 스타일을 걷어내고
  `[hidden]` 일 때 그려지지 않도록 했습니다.
- **`입장 다시 선택` → `역할 다시 선택`**: 말씀하신 대로 바꿨습니다. 다만 화면 전체에서
  이 개념을 부르는 말을 `개발자 안내`·`운영자 안내`·`역할 선택` 으로 함께 맞췄습니다
  (한 화면만 바꾸면 다른 화면과 말이 어긋납니다).

### 4-4. 시험용 찌꺼기 파일이 반입물에 실리던 통로 차단

검증용으로 만든 임시 DAG 카탈로그가 반입 대상 디렉터리에 남아 있으면
**그대로 사내에 실려 갈 수 있는** 상태였습니다. 패키징이 그런 파일을 발견하면
**중단**하도록 막았습니다(실제로 이번에 한 번 걸러졌습니다).

| 스케줄 정규화 계약 | 이번 판에 명부로 들여옴(수동 실행 시 통과 확인) |

자동으로 잡히지 않습니다.** 반입 자체를 막을 문제는 아니지만, 해당 부분을 수정하실 때는
수동 확인을 부탁드립니다. 검사 보강은 다음 판에서 진행합니다.

또 하나, 가이드 화면(`/airflow/guide`)의 "번들 소스에서 무엇이 생성되는지" 안내는
화면 구조가 바뀌면서 **문서 내용과 실제 코드가 일치하는지 확인하던 검사가 참조를 잃었습니다.**
화면은 정상 표시되지만, 안내 문구가 코드와 어긋나도 자동으로는 잡히지 않는 상태입니다.
